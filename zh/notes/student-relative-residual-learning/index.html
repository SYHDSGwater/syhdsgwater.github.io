从 teacher-centric quality filtering，走向 student-relative residual learning。

训练一个弱 SWE agent 时，目标很清楚：收集正确轨迹，过滤错误动作，然后做 SFT。训练一个已经很强的 agent 时，问题发生了变化。

传统筛选回答的是：这条轨迹好不好？

我们还需要回答另一个问题：这条好轨迹，对当前学生还新不新？

这篇文章的核心观点是：对于已经经过大量 agentic post-training、拥有成熟行为策略的 SWE SLM，数据选择应该从 teacher-centric quality filtering 转向 student-relative residual learning。数据质量不再只是轨迹的绝对属性，而是“数据 × 当前学生 × 学生实际会访问的状态”的相对属性。

SWE-Lego、SWE-Master 等方法仍然是必要的第一层筛选；在此之后，teacher-forced NLL 是一个有效、廉价的第二层指标，可以近似衡量候选轨迹对当前学生还剩多少信息。更进一步，我们不应只在 teacher 已经走完的成功轨迹上训练，还应尽可能从 student rollout、student failure state 和 student pass@k 难度中选择数据，使监督分布更接近部署时真正遇到的状态。

质量筛选决定轨迹是否值得被任何模型学习；残余学习决定其中哪些行为，仍值得被这个学生学习。

#1. 为什么我们原本相信 SFT

近一年的 SWE agent 研究给出了一个非常一致的经验：SFT 往往是小模型能力增长中最划算的阶段。

SWE-Lego 只依靠高质量数据、错误动作 masking 和难度课程，就让 Qwen3-8B 与 Qwen3-32B 在 SWE-bench Verified 上达到 42.2% 和 52.6%；再加 TTS@16 后分别达到 49.6% 和 58.8%。1 Orchard 的 Qwen3-30B-A3B-Thinking 在 SFT 后达到 64.3%，继续加入 RL 后为 67.5%：在这个实验里，大部分能力已经由 SFT 建立，RL 提供最后几个点的增益。2 SWE-Master 也把 teacher rollout、数据清洗、long-horizon SFT、execution-feedback RL 和 inference scaling 组织成同一条完整流水线。3

这些工作建立了今天最常见的、以 teacher 为中心的数据配方：

  1. 从 SWE-rebench、SWE-smith、Scale-SWE 等 issue pool 采样；
  2. 用强 teacher 在真实容器中 rollout；
  3. 只保留测试通过、格式正确、长度合理的轨迹；
  4. mask 错误或低效动作，并按难度或长度组织课程；
  5. SFT 后再用 RL 或 test-time scaling 榨取剩余能力。13

当学生很弱时，这套方法十分有效。因为“正确的 teacher 轨迹”通常也意味着“学生尚未掌握的轨迹”。但当 base model 本身已经是一个较强 agent 时，这两个集合开始分离：teacher 可以完成，不代表 student 不会；student 不会，也不代表完整 teacher 轨迹就是它最容易吸收的监督形式。

#2. 转折：强模型不一定需要你的 SFT 数据

TMax 给出了一个几乎理想的对照实验：同一份 TMax-SFT 数据、相近的训练配方，对旧的 Qwen3-8B 有益，却让经过大量后训练的 Qwen3.5-9B 退化。Terminal Bench Lite 上，Qwen3-8B 从 7.3% 提升到 11.5%，Qwen3.5-9B 却从 41.9% 降到 35.5%。TMax 的解释是，Qwen3.5 已经形成更成熟的 terminal-agent policy，较弱 teacher 的模仿数据带来的新信息不足以抵消策略漂移。4

我们进一步用两个模型各自的官方 chat template，在相同的 1,000 条 TMax-SFT 轨迹上计算 assistant-token teacher-forced NLL：

StudentToken NLLBits per byte相同数据上的 SFT 结果
Qwen3.5-9B0.2740.11441.9 → 35.5
Qwen3-8B0.7920.3237.3 → 11.5

两者的 token NLL 相差 2.89 倍；排除 tokenizer 粒度影响后的 bits per byte 仍相差 2.84 倍。也就是说，TMax 数据对 Qwen3-8B 是明显的新分布，对 Qwen3.5-9B 却已经高度熟悉。NLL 与两者相反的 SFT 结果恰好对齐。4

NLL 是学生相对的信息指标

NLL 在这里回答的不是“轨迹是否正确”，而是：给定 teacher 已经走出的正确历史，学生预测下一段 reasoning、action 和停止信号有多困难。

NLL⁡(D∣M)=−1N∑t=1Nlog⁡pM(yt∣x,y<t)\operatorname{NLL}(D\mid M)=-\frac{1}{N}\sum_{t=1}^{N}\log p_M(y_t\mid x,y_{<t})NLL(D∣M)=−N1​t=1∑N​logpM​(yt​∣x,y<t​)

NLL 很低，说明轨迹的大部分 token 已经落在学生熟悉的分布中；NLL 较高，说明其中可能包含学生尚未掌握的行为。当然，高 NLL 也可能来自格式不兼容、不可表达的 teacher policy 或噪声，因此它必须放在质量筛选之后，而不是替代质量筛选。

#3. SFT 真正在学习什么

Agentic SFT 并不直接优化 issue resolve。它在 teacher 访问过的历史状态上，最大化 teacher 下一段 reasoning、tool call 与终止动作的似然：

LSFT=−Eh∼dT, a∼πT(⋅∣h)[log⁡πθ(a∣h)].\mathcal{L}_{\mathrm{SFT}} =-\mathbb{E}_{h\sim d_T,\,a\sim\pi_T(\cdot\mid h)} \left[\log \pi_\theta(a\mid h)\right].LSFT​=−Eh∼dT​,a∼πT​(⋅∣h)​[logπθ​(a∣h)].

其中 dTd_TdT​ 是 teacher 与特定 harness 交互产生的状态分布。固定数据上的交叉熵等价于最小化 DKL(πT∥πθ)D_{\mathrm{KL}}(\pi_T\Vert\pi_\theta)DKL​(πT​∥πθ​) 的经验形式，也就是常说的 forward KL；但这个约束只在 h∼dTh\sim d_Th∼dT​ 的状态上成立。部署时，模型面对的是自己过去动作诱导出的 h∼dπθh\sim d_{\pi_\theta}h∼dπθ​​。一次错误搜索、编辑或验证会把它带到 teacher 数据从未覆盖的历史，后续误差便可能沿长轨迹累积。这是经典 imitation learning 的 distribution-shift 问题。19

因此，SFT 的能力增益更适合被理解为三件事：

  1. 接口与状态对齐。 学会在给定 harness 中读取 observation、调用工具、编辑、测试和 submit。
  2. 重塑行为先验。 提高有效定位、修改、验证和停止模式的概率，压低无效动作。
  3. 迁移可复用程序。 从具体轨迹中抽取跨 issue 可复用的搜索与修复模式。

这也解释了 SFT 何时会失效：student 可能已经掌握前两项；teacher 的长程程序可能超出 student 的表达能力；或者训练只覆盖 teacher 会访问的“干净状态”，没有教会 student 如何从自己的错误中恢复。训练 loss 下降只能说明模型更像 teacher，不能保证它在自己的状态分布上更会解决问题。

对强 agent 来说，理想数据不再是完整复制 teacher policy，而是学习两者之间仍有用、且 student 可以吸收的行为残差：

training value≈correctness×residual information×learnability×target relevance×student-state coverage.\text{training value} \approx \text{correctness} \times \text{residual information} \times \text{learnability} \times \text{target relevance} \times \text{student-state coverage}.training value≈correctness×residual information×learnability×target relevance×student-state coverage.

NLL 对应其中的 residual information，却不能单独代表 learnability 或 state coverage。这一点对理解后面的实验很关键。

#4. v14.d：一份“看起来没有问题”的 16K 数据

我们的 SFT v14.d 使用 Orchard-SWE 中 MiniMax-M2.5 生成的成功轨迹。最终训练集包含 16,124 条 trajectories、10,551 个 manifest issues：72.8% 来自 Scale-SWE，27.2% 来自 SWE-rebench。筛选要求外部 resolved、协议有效、无 Git 历史泄漏、无测试污染、没有最终未修复的显式自测失败；训练保留完整 thinking 和多轮 observation。

从传统标准看，这是一份相当理想的数据：真实 issue、真实执行环境、强 teacher、成功轨迹、完整长程上下文。Orchard 自身也已经证明这套数据和训练框架可以显著增强 Qwen3 系列。2

训练使用 Qwen3.5-4B FullFT、64K context、2 epochs、global batch 32、peak LR 1e-5。W&B API 返回的完整 1,008-step 日志显示：全程 update-loss 均值为 0.243，最后 50 步为 0.214；held-out loss 从 0.2646 持续降到 0.2541；1,008 个 loss 和 gradient norm 均为有限值。5

SFT v14.d training log

换句话说，优化没有失败，模型确实学会了更好地预测 MiniMax-M2.5 的轨迹。独立 teacher-forcing 也给出相同结论：基座在 v14.d train-300 上的 token NLL 为 0.307，SFT 后降至 0.211；validation-256 从 0.300 降至 0.252。15

但闭环结果没有出现预期增益。修复旧评测中“历史 assistant reasoning 未进入后续 context”的 chat-template 问题后，v14.d 在最终 500 题合并结果中严格通过 34.2%，只有 53.6% 的轨迹主动 submit，40.6% 跑满 250 turns。它学会了 teacher-forced 目标，却仍然频繁陷入长程探索、无法收束。6

评测口径。 34.2% 是项目最终合并结果，前 200 题包含选择性重跑，不是统一配置下的一次无偏 pass@1；统一配置的 301–500 题严格通过率为 30.0%。这个限制影响分数的 leaderboard 可比性，但不改变大量 turn-cap 与低 submit 所揭示的行为问题。6

这提示我们：resolved trajectory 是 teacher 能完成的策略，不一定是 4B student 能稳定执行的策略。 一个强 teacher 可以探索很久并在最后修好；小模型可能只学到探索风格，却没有能力复现完整的定位—编辑—验证—停止链条。

前两组都来自公开的 Qwen3-8B 成功训练配方：SWE-Lego 只用 SFT 就获得 +34.6 points；Klear-AgentForge-8B-SFT 获得 +30.2 points。1 它们在同一 scorer 下分别落在 0.738 和 0.812；再加上 TMax 的 0.792 与正向 SFT 结果，证据开始从“跨模型方向一致”变成“同 backbone 聚集在同一邻域”。截断并没有制造这一排序：只看完整未截断轨迹，两个值变为 0.758 与 0.824。

这仍不是一条因果曲线。500 条只是各自公开 SWE 轨迹族的样本，不是完整训练 mixture；两个项目还使用不同的数据组合、mask、课程与 agent harness。尤其 AgentForge 的 0.812 略高于 0.8。因此，更诚实的结论是：现有成功案例支持一个以 0.5–0.8 为核心、上缘约到 0.85 的候选工作区间，而不是 0.8 的硬阈值。我们在下文继续把“0.5–0.8 黄金区间”写成待检验假说，而不是已经证明的定律。

这些数字不支持一个跨模型通用的 NLL 阈值。GRAPE 在每个 instruction 的多个正确 response 中选择 student likelihood 更高、也就是更贴近 student 原有分布的候选，结果优于简单模仿最强 teacher；这说明“可吸收性”本身就是训练价值的一部分。17 但如果只选最低 NLL，又会优先得到 student 已经会的内容。RSR 的结果提供了更细的解释：好的 reasoning trajectory 往往具有足够的绝对 surprisal，同时关键 token 在 student 的候选排序中仍然靠前——它陌生，但并不离开 student 可理解的行为邻域。18

因此，我们把当前实验中的 0.5–0.8 附近只视为后续 pilot 值得重点覆盖的经验区间，而不是“最优数据”的判定规则。更可靠的目标是：在正确性与过程质量门控之后，寻找 NLL 适度偏高、token rank 仍合理、并且对应 student 真实失败模式 的轨迹。模型、tokenizer、模板、mask 和领域变化后，区间都会移动；跨 tokenizer 时还应报告 BPB 或 nats/character。

AxiaoDBL 的公开训练日志给出了方向一致的线索：其前 50 updates 均值为 0.578，第一轮均值约 0.525，明显高于 v14.d 的 0.281 与 0.270 附近。它只用 2,784 条训练轨迹、2 epochs，就报告了 55.0% SWE-bench Verified；相对其模型卡中的 44.8% base 是 +10.2 points。7

这里不把两边 trainer loss 当成严格统一的 token NLL：AxiaoDBL 的全程 update-loss 均值其实是 0.438，且它使用不同的 action mask、课程和 reduction。但在低成本 preflight 阶段，“约 0.55 的早期/第一轮训练信号”仍然是有价值的方向性证据，不应因为口径不完全一致而把这条线索完全丢掉。

#6. 比 issue source 更关键的变量：rollout teacher

AxiaoDBL 作者说明，其训练 issue pool 是 PrimeIntellect/SWE-Lego-Real-Data-Verified 的子集，rollout teacher 是 DeepSeek-V4-Flash。79 Prime 数据来自 SWE-rebench，并经过测试 ID 修复与 gold-patch F2P/P2P 验证；这是一种高质量的传统筛选。

但 issue pool 并不能解释全部差异。我们对 v14.d manifest 与 Prime Verified 的 4,323 个 resolved issues 做 exact instance-id overlap：

两套训练并非完全不同的 issue 世界；v14.d 已覆盖 Prime pool 的相当一部分。更大的区别是，同类 issues 上生成监督行为的 teacher 不同：MiniMax-M2.5 vs DeepSeek-V4-Flash GA/0731，以及随后的 action masking 与 curriculum 不同。

精确 teacher 版本同样重要。DeepSeek 官方说明，V4-Flash-0731 与 Preview 具有相同架构和规模，主要变化是重新 post-training；但 Terminal Bench 从 61.8 提升到 82.7，NL2Repo 从 39.4 到 54.2，DeepSWE 从 7.3 到 54.4，Toolathlon 从 49.7 到 70.3。10

SWE-Router 的 DeepSeek-V4-Flash SBV traces 在 0731 正式版发布前生成，属于 Preview 时代。12 我们在这份 Preview trace 上测得的 Qwen3.5-4B NLL 是 0.355，不能代替 AxiaoDBL 的 GA teacher 数据。根据作者的社区补充，本稿将 AxiaoDBL teacher 记为 GA/0731 时代；公开 discussion 页面只保留了 DeepSeek-V4-Flash 别名，没有不可变 revision hash。8

这组证据支持一个更强的工程结论：

数据集的单位不是 issue，也不是 resolved trajectory，而是 issue × exact teacher checkpoint × harness × reasoning effort × sampling × loss mask。

一个 benchmark 分数很高的 teacher 不一定能为当前学生提供新能力；同一模型家族的不同 post-training 版本，也可能产生完全不同的训练价值。真正廉价的检验不是看 teacher 名字，而是直接计算学生在候选 teacher traces 上的 NLL。

#7. 从 teacher quality 到 student-relative residual

SWE-Lego 通过执行验证、错误动作 masking 和难度课程提升轨迹质量；SWE-Master 结合 reward、格式、长度、BoN 难度和 LLM judge 过滤；Orchard 进一步用 credit assignment 从失败轨迹中保留有价值的片段。13

这些方法主要解决前三类问题；强 student 还需要加入后两类：

维度典型问题典型指标
正确性patch 是否真的修好F2P / P2P、gold patch validation

正确性和过程质量决定“能不能学”，其余三维决定“值不值得让这个学生学”。DEITA、SWE-Lego、SWE-Master 一类方法首先建立干净的 teacher pool；IFD 用 student 对 instruction-response 的相对困难度做筛选；LESS 用目标任务的梯度影响估计 relevance；GRAPE 与 RSR 则分别从 distribution fit 和 informative alignment 补充 student-relative 信号。1172123

对于较老或已经被广泛训练过的 issue source，还应额外考虑参数记忆和污染风险；较新的 SWE-rebench、Scale-SWE，以及 Prime/SWE-Lego 式二次环境验证，仍然更适合作为上游池。但筛选不应停在这里。NLL 可以删除“绝对正确、相对冗余”的数据；rank 与执行验证可以排除“很惊讶，但其实不可学或错误”的数据；student rollout 则决定这些监督是否对应模型部署时真的会犯的错。

这就是 student-relative residual learning：

不是把最强 teacher 的全部行为压进 student，而是在高质量行为中，寻找并教授 student 当前策略相对于目标策略的可学习残差。

#8. 为什么需要“近似 on-policy”

纯 teacher rollout 是 off-policy 的：teacher 决定看哪些文件、运行哪些命令、进入哪些中间状态，student 只在这些状态上模仿。即使最终 patch resolved，这些状态也未必是 student 执行时最需要帮助的地方。SWE agent 的 horizon 又很长，早期一次分叉足以让后半段 teacher supervision 失去对应关系。

经典 DAgger 的思路是在 learner 自己诱导的状态上查询 expert；语言模型中的 GKD 也让 student 先生成，再由 teacher 在 student-generated sequences 上提供监督，并允许使用不同于固定 forward-KL SFT 的目标。19 对真实 SWE 环境而言，完全 on-policy 的 teacher annotation 成本很高，但可以采用几种近似：

  1. 先让 student rollout，按 pass@k 和失败类型找到“偶尔成功”或可恢复的 issues；
  2. 从 student 的失败 prefix、错误 edit 或验证循环开始，让 teacher 纠偏，而不是总从干净初始状态重跑；
  3. 保留 student 已经正确的动作，只监督 teacher 相对 student 的关键 residual action；
  4. 训练若干 checkpoint 后重新计算 NLL/rank 并重采样，使数据随 student policy 一起移动。

这些方法并不会自动消除 forward KL 的全部局限，但它们把期望中的状态分布从 dTd_TdT​ 推向 dπθd_{\pi_\theta}dπθ​​：模型开始在“自己真的会到达的地方”学习，监督也更集中于当前策略的缺口。对于已经较强的 agent，这通常比继续扩大静态 teacher-success 数据更接近真正的能力拓展。

#9. 一个廉价的训练前检查

在启动数千条 rollout 或完整 SFT 之前，可以先做下面的 preflight：

  1. 先做传统质量筛选。 环境可执行、patch resolved、F2P/P2P 有效、无泄漏、动作格式正确。
  2. 冻结计分协议。 使用待训练的 student checkpoint、实际训练 tokenizer/chat template、完整历史 reasoning 和相同 loss mask。
  3. 抽样 100–1,000 条候选轨迹计算 NLL。 同时报告 token-weighted mean、逐轨迹分位数和 target-token 数；跨 tokenizer 再报告 BPB。
  4. 加入学生自己的 rollout 作为锚点。 如果 teacher NLL 接近 self-rollout NLL，新增信息可能有限；如果适度更高、rank 仍合理且轨迹经过验证，它更可能处于可学习的新区域。
  5. 估计 student-relative issue difficulty。 用 pass@k 区分 always-pass、mixed 和 always-fail；优先检查 mixed issues 与可恢复失败，而不是默认所有 resolved teacher issues 等价。
  6. 按行为拆分。 单独统计 reasoning、工具动作、第一次有效 edit、验证和 submit；全序列均值可能掩盖少数关键决策。
  7. 先跑小规模闭环 pilot。 除 pass@1 外，跟踪 submit rate、首次 edit、empty patch、无进展 turns、turn/context cap，再决定是否扩到完整训练。

我们目前会联合使用四组廉价信号：benchmark pass@1/pass@k 衡量学生已有能力；teacher trace NLL 与 token rank 衡量候选监督的新颖度和可吸收性；student rollout 提供自身状态分布的锚点；小规模闭环行为指标检验 teacher forcing 的收益能否转化为真实 rollout。

#10. Next step — Coming soon

下一轮实验会直接检验 residual-learning 假说，而不是继续比较更多 teacher 名字。

实验一：NLL 是否足够，还是需要 informative alignment？ 在统一 Qwen chat template、完整历史 reasoning 和相同 loss mask 下，把 assistant targets 拆成 reasoning、tool name/arguments、edit、test/verification 与 submit/termination，逐类计算 NLL、token rank 和 RSR。

实验二：控制质量后的数据分桶。 对相同 issue pool 中通过执行验证的轨迹，按 <0.5、0.5–0.8、0.8–1.1、>1.1 分桶，再在每桶内匹配 assistant token 预算、repo、长度和 teacher。每桶进一步区分低 rank 与高 rank，直接检验 0.5–0.8 是稳定工作区间、柔性边界，还是当前少量实验形成的巧合。

实验三：引入近似 on-policy 的 issue/state selection。 用 student pass@k 将 issues 分为 always-pass、mixed 与 always-fail，并加入从 student failure prefix 出发的 teacher correction。比较静态 teacher-success SFT、student-difficulty filtering，以及 failure-state residual SFT。

实验四：看能力，而不只看 loss。 控制 issue 数、assistant target tokens、repo 分布、训练 steps 与 teacher，除 resolve rate 外，同时测 invalid tool calls、定位与首次有效 edit、reproduction/regression test、premature submit、turn/context cap，并做 checkpoint-level ID/OOD 与 cross-harness 评测。

一个可证伪的预测是：在质量门控之后，中高 NLL、低 token rank、来自 student mixed/failure states 的轨迹，会比单纯最低 NLL、最高 NLL 或随机数据带来更好的闭环收益；提升应首先出现在 student 原有失败模式，而不是只表现为输出格式或长度变化。

#结论

传统 SWE 数据筛选仍然重要，但它只保证轨迹“好”。当目标是拓展一个已经很强的 SWE Agentic SLM 时，我们还必须判断轨迹是否对这个学生有信息、是否可学，以及是否覆盖它实际会进入的状态。

TMax 展示了同一份 SFT 数据可以增强 Qwen3-8B、却削弱 Qwen3.5-9B；我们的 NLL/BPB 测量提前暴露了两者对数据熟悉度的巨大差异。v14.d 展示了 16K 条经过严格筛选的成功轨迹、稳定下降的训练与验证 loss，仍然可能无法产生更好的闭环策略。AxiaoDBL 则表明，更少但对学生更新鲜、teacher 更匹配并配合 action-level filtering 的轨迹，可能带来更大收益。

因此，训练数据的目标不应只是：

找到更多正确轨迹。

而应该变成：

在正确轨迹中，找到当前学生尚未掌握、但有能力学会，并且会在真实 rollout 中用到的那一部分。

这意味着数据工程的重心需要从 teacher-centric quality filtering 继续向 student-relative residual learning 移动。NLL 不是这个问题的最终答案，但它足够便宜、足够直接；与 token rank、student difficulty 和 student-generated states 联合后，它比只看 teacher benchmark、issue source 或训练 loss 更接近我们真正想知道的东西。
